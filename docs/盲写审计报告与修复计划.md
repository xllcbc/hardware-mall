# 盲写审计报告与修复计划

> 审计日期：2026-09-02
> 审计范围：`hardware-mall-backend` 全量 Java 源码（129 个文件）+ `hardware-mall-admin` 与 `hardware-mall-uniapp` 前端调用
> 审计方法：4 个并行探查代理交叉验证（后端内部引用一致性、前后端接口对齐、规范与逻辑隐患、DB 与代码对齐），关键高危项已人工复核

## 一、总体结论

- 跨文件引用层面（接口/实现、常量、工具类签名、实体字段、Bean 注入、事件、Mapper SQL）基本干净，**无编译级盲写断点**。
- 但存在大量典型的"单文件看是对的、放全局就错"型 bug：**高危 6 项、中危约 12 项、低危若干**。
- 高危问题集中在：订单取消竞态资损、用户封禁失效、小程序头像上传 404、管理端启停接口 400、spec_hash 协议漂移。

## 二、审计发现

### 2.1 高危（功能必然失败 / 资损风险，已人工复核）

| # | 问题 | 位置 |
|---|------|------|

| H3 | **小程序头像上传 404**：调用不存在的 `/user/upload/avatar`（后端只有 `/api/admin/upload/avatar` 且有 `@RequireAdmin`），且误读响应 `data.data` 应为 `data.data.url` | `uniapp/src/pages/user/edit.vue:116,125` |

### 2.3 低危（本次不修复，留档）

- token 拉黑无 TTL（内存泄漏）、`deleteSku` 不清 `sku:stock`、事务提交前写 Redis
- `PaymentRecord.getStatus()` 为 null 时 NPE（Integer == int 拆箱，多处）
- 限流/库存失败队列等 Redis key 魔法字符串游离于 `RedisConstants` 外、`PREFIX_RATE_LIMIT` 常量重复定义
- 测试 schema 缺全部 UNIQUE KEY（与生产漂移）、`payment_record` DDL 无 `IF NOT EXISTS`
- 死接口/死代码：admin 端 `/spu/category/*` 5 个、`/user/product/{id}/specs`、`admin_remark` 死列、FULLTEXT 索引无人用、`OrderItem.productId`/`cancelTime` 等前端类型声明漂移
- 退款金额 `longValue()` 应为 `longValueExact()`、`StockSyncRetryJob` 无分布式锁

## 三、修复计划

### Phase 1 — 高危 6 项

#### H1 取消订单竞态资损 ✅ 已完成

**目标**：`OrderServiceImpl.cancelOrder` / `autoCancelOrder`

**改动**：
- 将"查状态 → 还库存 → 无条件 updateById"改为：CAS `WHERE id=? AND status=1` 条件更新
- `affected==0` 则抛异常使整个事务回滚，与同文件 `confirmReceive` 的既有 CAS 风格对齐
- 库存恢复移到 CAS 成功之后，避免"还了库存但订单没取消"的问题
- `autoCancelOrder` 同型改造，`affected==0` 返回 false

**验证**：编译通过；OrderServiceImplTest 的 Mockito 插件初始化问题是环境配置问题，与本次修改无关

---

#### H2 封禁失效 + refresh 链路

**目标**：`UserServiceImpl` + `UserController` + `AdminAuthController`

**改动**：
- `login()`：已存在用户若 `status==DISABLED` 抛 `BusinessException("账号已被禁用")`
- `refreshToken(userId)` 改签名 `refreshToken(userId, oldToken)`：校验用户状态、claims 补 `role`、新 token `sAdd` 登记、旧 token 拉黑（带 TTL，对齐 `logout` 写法）
- 同步改 `UserController.refresh` 与 `AdminAuthController.refresh` 两个调用方及测试

**验证**：`UserServiceImplTest` 补禁用登录、refresh 登记/拉黑场景

---

#### H3 小程序头像上传 404

**目标**：新增 `controller/user/UserUploadController` + 前端 `edit.vue`

**改动**：
- 新增 `POST /api/user/upload/avatar`（登录态、限图片、复用 OssService，路径 `avatar/`）
- `edit.vue:125` 改读 `data.data.url`

**验证**：手动上传测试

---

#### H4/H5 启停接口 400

**目标**：`AdminUserController.updateUserStatus`、`AdminLogisticsController.updateStatus`

**改动**：
- `@RequestParam` → `@RequestBody Map<String,Integer>`（与同文件 region 接口风格一致）

**验证**：前端启停操作测试

---

#### H6 spec_hash 漂移

**目标**：`SkuServiceImpl`

**改动**：
- 规格去重不再依赖存储的 hash 字符串相等：改用 specs 归一化 key（排序后 `templateId:itemId` 多重集，`templateId==null` 记 `"default"`）做匹配，兼容 seed 的 `auto_c*_i*` 与 MD5 两种存量 hash
- 顺带消除 null templateId 排序 NPE
- `createSku` 保存时若归一化 key 已存在则跳过/报错
- 更新 `SkuServiceLogicTest`

**验证**：`SkuServiceLogicTest` 补 seed 兼容场景

---
