# 多级用户定价设计文档

## 1. 背景

当前系统只有两档价格：`sku.price`（零售价）与 `sku.wholesale_price`（批发价，绝对金额），用户通过 `user.user_group` 区分 1-零售 / 2-批发商。

实际业务需要多档批发价，且**同一等级在不同商品分类下享受的折扣不同**。例如锁类 A 级 0.8、胶类 A 级 0.7，互不影响。

本方案把定价从"每个 SKU 存多份价格"改为"**单一零售价 × 等级分类倍率**"，避免价格字段随等级数量膨胀。

## 2. 核心决策

| 编号 | 决策 |
| --- | --- |
| D1 | 基数恒为 `sku.price`（零售价）；成交单价 = 零售价 × 倍率 |
| D2 | 倍率取值区间 `(0, 1]`，不支持 0 元；保存时校验拒绝 >1 |
| D3 | 零售是等级表中的一档，倍率恒为 1.0，不可改名、不可删除 |
| D4 | 一个用户只属于一个等级；新注册用户默认零售 |
| D5 | 规则是**等级 × 分类的完整矩阵**，每格独立配置，不存在"等级系数 × 分类系数"相乘 |
| D6 | 矩阵为稠密语义：新增等级必须填满所有分类才允许启用 |
| D7 | `category` 只有一层，无父子继承，矩阵不存在冲突解析 |
| D8 | 不做 SKU 级例外；`spu` 增加 `exclude_discount` 布尔开关，命中时任何等级都按零售价 |
| D9 | 倍率 `DECIMAL(6,4)`；单价 `HALF_UP` 保留 2 位；逐行取整后乘数量再求和 |
| D10 | 下单瞬间解析价格并写快照，订单创建后金额冻结；改等级/改倍率只影响后续下单 |
| D11 | 用户端只显示当前用户能拿到的价格；不显示等级名称、折扣率、划线价、价格性质标签 |
| D12 | 商品缓存中性化：只存零售区间，倍率单独缓存；改倍率不失效商品缓存 |
| D13 | 规则改动立即生效，不做生效时间、不做规则版本、不做审计日志 |
| D14 | 后台不区分权限，全部归现有管理员角色；改倍率需二次确认 + 影响面提示 |
| D15 | 不引入成本价保护 |
| D16 | 废弃 `sku.wholesale_price`、`user.user_group`、`order_item.price_type` |

## 3. 数据模型

### 3.1 新增：用户等级表 `user_level`

```sql
CREATE TABLE IF NOT EXISTS `user_level` (
    `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '等级ID',
    `name` VARCHAR(50) NOT NULL COMMENT '等级名称，如：零售/批发A/批发B',
    `is_retail` TINYINT NOT NULL DEFAULT 0 COMMENT '是否零售等级：1-是（倍率固定1.0，不可改名/删除），0-否',
    `sort_order` INT NOT NULL DEFAULT 0 COMMENT '排序权重，数值越大越靠前',
    `status` TINYINT NOT NULL DEFAULT 1 COMMENT '等级状态：1-启用，0-停用',
    `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `update_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_name` (`name`),
    KEY `idx_status_sort` (`status`, `sort_order` DESC)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci COMMENT='用户等级表';
```

初始化数据（`id = 1` 由脚本固定写入，`user.level_id` 依赖该默认值）：

```sql
INSERT INTO `user_level` (`id`, `name`, `is_retail`, `sort_order`, `status`)
VALUES (1, '零售', 1, 100, 1);
```

零售等级**不写矩阵行**，定价时由代码短路为 1.0，因此不参与矩阵完整性校验。

### 3.2 新增：等级分类倍率表 `level_category_discount`

```sql
CREATE TABLE IF NOT EXISTS `level_category_discount` (
    `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键',
    `level_id` BIGINT UNSIGNED NOT NULL COMMENT '用户等级ID',
    `category_id` BIGINT UNSIGNED NOT NULL COMMENT '商品分类ID',
    `rate` DECIMAL(6,4) NOT NULL COMMENT '倍率(0,1]，成交价=零售价×rate',
    `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `update_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (`id`),
    UNIQUE KEY `uk_level_category` (`level_id`, `category_id`),
    KEY `idx_category_id` (`category_id`),
    CONSTRAINT `fk_lcd_level` FOREIGN KEY (`level_id`) REFERENCES `user_level` (`id`),
    CONSTRAINT `fk_lcd_category` FOREIGN KEY (`category_id`) REFERENCES `category` (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci COMMENT='等级分类倍率表';
```

### 3.3 表结构变更

| 表 | 变更 |
| --- | --- |
| `user` | 新增 `level_id BIGINT UNSIGNED NOT NULL DEFAULT 1 COMMENT '用户等级ID'`；删除 `user_group` |
| `spu` | 新增 `exclude_discount TINYINT NOT NULL DEFAULT 0 COMMENT '不参与折扣：1-是，0-否'` |
| `sku` | 删除 `wholesale_price` |
| `order_item` | 新增 `level_id` / `level_name` / `discount_rate`；删除 `price_type` |

```sql
ALTER TABLE `order_item`
    ADD COLUMN `level_id` BIGINT UNSIGNED NULL COMMENT '下单时用户等级ID快照',
    ADD COLUMN `level_name` VARCHAR(50) NULL COMMENT '下单时用户等级名称快照',
    ADD COLUMN `discount_rate` DECIMAL(6,4) NULL COMMENT '下单时适用倍率快照';
```

订单快照三列允许为 `NULL`，用于兼容历史订单。

## 4. 定价链路

### 4.1 职责拆分

```text
PricingRuleService（新增，带缓存）
  rateFor(levelId, categoryId)   查询倍率：零售等级短路 1.0；无规则回落 1.0
  矩阵读写、一键填充、复制等级、完整性校验
  resolveRetailLevelId()         查询零售等级 ID

PriceService（改造为纯函数）
  resolveUnitPrice(BigDecimal retailPrice, BigDecimal rate)
    校验入参 → 零售价 × 倍率 → HALF_UP 保留 2 位
  不注入 Mapper、Redis、缓存服务
```

`PriceService` 必须保持纯函数，这是 `docs/商品缓存边界与依赖.md` 已有的维护规则，本方案继续遵守。

### 4.2 解析流程

```text
Controller / CartService / OrderService
  -> 取得 spu.exclude_discount
  -> PricingRuleService.rateFor(levelId, spu.categoryId)
       exclude_discount = 1 → rate 固定 1.0
  -> PriceService.resolveUnitPrice(sku.price, rate)
  -> 行小计 = 单价 × 数量（逐行取整后求和）
```

商品列表的区间价同源：`minPrice = retailMinPrice × rate`，`maxPrice = retailMaxPrice × rate`。

**等价性说明**：同一个 SPU 的 SKU 必然同属一个分类，即整张 SPU 使用同一个倍率。四舍五入是单调不减运算，因此"区间两端乘完取整"与"逐 SKU 取整后取最小/最大"结果一致，不会出现列表价与详情价不一致。

### 4.3 边界处理

| 场景 | 行为 |
| --- | --- |
| SPU 无 SKU | 以 `spu.original_price` 视为零售价，同样乘倍率 |
| 矩阵缺格 | 按 1.0 兜底，不阻断下单 |
| `spu.exclude_discount = 1` | 任何等级按零售价 |
| 用户 `level_id` 为空或等级已停用 | 沿用用户当前 `level_id` 的倍率；`level_id` 为空时按零售 1.0 |
| 商品更换分类 | 倍率随之变化，无需额外处理 |

## 5. 缓存改造

### 5.1 商品缓存中性化

`ProductListCacheItem` 删除 `wholesaleMinPrice` / `wholesaleMaxPrice`，只保留 `retailMinPrice` / `retailMaxPrice`。

缓存 Key 版本升级（结构变更，避免旧 JSON 反序列化失败）：

| 旧 Key | 新 Key |
| --- | --- |
| `product:detail:v3:{spuId}` | `product:detail:v4:{spuId}` |
| `product:list:v3:*` | `product:list:v4:*` |
| `product:recommend:v3` | `product:recommend:v4` |
| `product:search:v1:*` | `product:search:v2:*` |

旧版本 key 等待自然过期或手动清理，与现有维护规则一致。

### 5.2 新增倍率缓存

| Key | 内容 | TTL |
| --- | --- | --- |
| `pricing:level:{levelId}` | 该等级的全部分类倍率 `Map<categoryId, rate>` | 1 小时 |
| `pricing:retail-level-id` | 零售等级 ID | 1 小时 |

失效规则：

| 数据变更 | 必须失效 |
| --- | --- |
| 矩阵倍率修改、批量填充、复制等级 | `pricing:level:{levelId}` |
| 等级停用/启用、删除 | `pricing:level:{levelId}`、`pricing:retail-level-id` |
| 用户等级变更 | 不失效任何缓存，只失效该用户 Token |

**改倍率不失效商品缓存**，这是本次缓存改造的核心收益。

## 8. 迁移方案

### 8.1 起点

`migration_2026-09-17_wholesale_pricing.sql` **从未执行**，生产与该库的起点是**加批发价字段之前的原始结构**（无 `user_group`、无 `wholesale_price`、无 `price_type`）。

但当前 `init.sql` 已包含这三列，因此本地库若由当前 `init.sql` 创建则**存在**这三列。

### 8.2 交付文件

1. `init.sql` 更新为最终结构（新库一步到位，不跑迁移脚本）；
2. 新增 `migration_2026-10-18_multi_level_pricing.sql`：唯一增量脚本，面向原始结构编写；
3. 删除 `migration_2026-09-17_wholesale_pricing.sql`（内容被完全覆盖且方向相反）。

### 8.3 幂等处理

MySQL 不支持 `ADD COLUMN IF NOT EXISTS`，脚本用 `INFORMATION_SCHEMA` + `PREPARE/EXECUTE` 判断后再执行，使"有批发价三列"与"没有"两种起点都能跑到同一终态：

```sql
SET @has_col := (SELECT COUNT(*) FROM INFORMATION_SCHEMA.COLUMNS
                 WHERE TABLE_SCHEMA = DATABASE()
                   AND TABLE_NAME = 'sku' AND COLUMN_NAME = 'wholesale_price');
SET @ddl := IF(@has_col > 0, 'ALTER TABLE `sku` DROP COLUMN `wholesale_price`', 'SELECT 1');
PREPARE s FROM @ddl; EXECUTE s; DEALLOCATE PREPARE s;
```

同样方式处理 `user.user_group`、`order_item.price_type`。

### 8.4 脚本步骤

1. 创建 `user_level`，写入零售等级（`id = 1`）；
2. 创建 `level_category_discount`；
3. `user` 新增 `level_id`；若存在 `user_group`：先把 `user_group = 2` 的用户迁到新建的"批发商"等级，再删除 `user_group`；
4. `spu` 新增 `exclude_discount`；
5. `sku` 删除 `wholesale_price`（存在才删）；
6. `order_item` 新增三列快照、删除 `price_type`（存在才删）；
7. 为新建的"批发商"等级填充全 1.0 矩阵（保证不会因缺口导致价格异常，待商家重配）。

### 8.5 回滚

回滚依赖数据库备份：改动前 `mysqldump` 全库快照，回滚时恢复备份并部署旧版本代码。脚本不提供逆向迁移。

### 9.2 验收用例

1. 零售用户查看商品，价格等于 `sku.price`；
2. A 级用户查看锁类商品（倍率 0.8），10.00 → 8.00；
3. A 级用户查看胶类商品（倍率 0.7），10.00 → 7.00；
4. 矩阵缺格时按零售价显示，且可正常下单；
5. `exclude_discount = 1` 的商品对所有等级均按零售价；
6. 单件 8.115 元的计算结果为 8.12（`HALF_UP`），数量 3 的行小计为 24.36；
7. 修改倍率后，商品列表缓存未被清除，价格立即变化；
8. 修改用户等级后，该用户全部 Token 失效，重新登录后价格切换；
9. 已创建订单的价格与等级快照在倍率修改后保持不变；
10. 小程序详情页与列表页均不出现划线价、"批发价"标签或等级名称。

## 10. 明确不做

- 成本价保护、利润统计
- SKU 级独立倍率
- 多分类归属（`spu.category_id` 仍为单值）
- 规则生效时间、版本回滚、审计日志
- 后台分级权限
- 限时活动价、赠品（倍率下限 >0）
- 用户端展示等级名称、折扣率、划线价

## 11. 实施顺序建议

1. 数据库：`init.sql` + 迁移脚本；
2. 后端实体与常量 → `PriceService` → `PricingRuleService` → 各业务 Service → Controller；
3. 缓存 key 版本升级与中性化改造；
4. 管理后台用户群体管理页与既有页面改造；
5. 小程序删除孤儿页面、清理价格展示；
6. 同步更新 `docs/商品缓存边界与依赖.md`（其中 `PriceService.resolve(sku, userGroup)` 的描述已过时）；
7. 补测试、跑 `mvn compile` 与前端构建。

## 12. 实施补充

- 零售等级固定启用，管理员不可改名、停用或删除；非零售等级创建后默认停用。
- 普通用户旧 Token 若缺少 `levelId`，后端直接返回 401，要求重新登录；管理员 Token 不携带等级，不受此限制。
- 订单明细的 `levelId`、`levelName`、`discountRate` 快照仅管理端接口返回，用户端订单接口隐藏这三个字段。
