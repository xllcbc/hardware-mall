# 商品缓存边界与依赖

## 目标

商品域缓存统一由 `ProductCacheService` 收口。业务服务不再自行拼接缓存 key、设置 TTL 或声明失效目标。

缓存只保存中性商品数据，不保存某个用户或用户组专属的最终价格。用户身份裁剪在缓存读取完成后，由 `PriceService.resolve` 完成。

## 模块职责

```text
ProductCacheService
  商品缓存 key、TTL、搜索关键词规范化
  sku:info 批量读取、缺失回填
  product:list / product:search / product:recommend / product:detail 读取

SkuService
  调用 ProductCacheService 批量读取 SKU
  补齐 sku:stock
  过滤已删除 SKU
  对外提供 Map<Long, Sku>

SpuService
  组装商品列表、搜索、推荐、详情的中性数据
  使用 UserContext + PriceService 生成当前用户价格视图

CartService / OrderService
  只调用 SkuService
  不接触缓存 key、RedisUtil 或 loader

ProductCacheInvalidationListener
  在事务提交后调用 ProductCacheService 的统一失效方法
```

## 缓存 Key

| Key | 内容 | TTL |
| --- | --- | --- |
| `sku:info:{skuId}` | SKU 基础信息，不包含库存 | 1 小时 |
| `sku:stock:{skuId}` | SKU 实时库存 | 无 TTL，启动预热 |
| `product:detail:v3:{spuId}` | SPU、规格、原始 SKU 中性数据 | 1 小时 |
| `product:list:v3:{categoryId}:{page}:{limit}:{status}` | 商品列表中性价格区间 | 1 小时 |
| `product:search:v1:{keywordHash}:{categoryId}:{page}:{limit}:{status}` | 搜索结果中性价格区间 | 10 分钟 |
| `product:recommend:v3` | 推荐商品中性价格区间 | 1 小时 |

搜索关键词先执行 `trim`、小写化和 Unicode NFKC 规范化，再计算 SHA-256。原始关键词不进入 Redis key。

## 读取边界

### 商品列表

```text
UserProductController
-> SpuService
-> ProductCacheService
-> PriceService.resolve(sku, userGroup)
-> ProductListVO
```

### 商品详情

```text
UserProductController
-> SpuService
-> ProductCacheService.getProductDetail
-> ProductSkuVO
-> 实时补齐库存
```

`/api/user/product/{id}/skus` 复用 `product:detail:v3:{spuId}`，不直接查询 SKU 表。

### 购物车和订单

```text
CartService / OrderService
-> SkuService.getSkuMapByIds
-> ProductCacheService.getSkusByIds
-> RedisUtil.multiGet(sku:info:*)
-> 缺失 SKU 单次批量回源并回填
-> 批量补齐 sku:stock
-> PriceService.resolve
```

## 失效依赖

| 数据变更 | 必须失效 |
| --- | --- |
| SKU 创建、价格修改、删除、复活 | `sku:info:{skuId}`、`product:detail:v3:{spuId}`、`product:list:v3:*`、`product:search:v1:*`、`product:recommend:v3` |
| SKU 库存变化 | `sku:stock:{skuId}` |
| SPU 名称、图片、状态、分类、价格修改 | `product:detail:v3:{spuId}`、`product:list:v3:*`、`product:search:v1:*` |
| SPU 推荐状态或推荐商品内容变化 | 普通 SPU 缓存，以及 `product:recommend:v3` |
| 用户分组变化 | 不失效商品缓存，只失效用户 Token |
| 购物车、订单写入 | 不失效商品缓存 |

所有 SKU 写路径统一发布 `ProductCacheInvalidationEvent`。监听器使用：

```java
@TransactionalEventListener(
    phase = TransactionPhase.AFTER_COMMIT,
    fallbackExecution = true
)
```

数据库事务回滚时不会触发商品缓存失效。

## 维护规则

1. 新增商品缓存读取入口时，必须通过 `ProductCacheService`。
2. 新增 SKU 或 SPU 写路径时，必须发布对应的缓存失效事件。
3. 商品缓存不得保存用户组专属价格。
4. `PriceService.resolve` 必须保持纯函数，不注入 Redis、Mapper 或缓存服务。
5. 商品缓存 key 版本变更时，旧版本 key 等待自然过期或手动清理。
