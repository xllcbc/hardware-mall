# Phase 6: CI/CD（GitHub Actions）— Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** GitHub Actions 自动化：push 到主分支 → 跑测试 → 构建 Docker 镜像 → SSH 登录生产服务器 pull & restart。小程序端用 miniprogram-ci CI 上传体验版。

**Tech Stack:** GitHub Actions self-hosted 或 hosted runners, Docker registry (Docker Hub 或 阿里云私有 registry), miniprogram-ci

**前置约束：** Phase 0-5 已 merge。在 `phase6-cicd` 分支执行。前提：用户必须准备一台云服务器、一个 GitHub repo 远端、Docker registry 账号、微信小程序私钥。

- [ ] **Step 1: 写部署 pipeline**

Create: `.github/workflows/backend-admin-deploy.yml`

```yaml
name: deploy-prod

on:
  push:
    branches: [main]
  workflow_dispatch:
    inputs:
      target:
        description: 'Deploy target (staging|prod)'
        required: true
        default: 'prod'

jobs:
  deploy:
    runs-on: ubuntu-latest
    needs: []
    env:
      DOCKER_REGISTRY: ${{ secrets.DOCKER_REGISTRY }}
      IMAGE_BACKEND: ${{ secrets.DOCKER_REGISTRY }}/hardware-mall-backend:${{ github.sha }}
      IMAGE_ADMIN: ${{ secrets.DOCKER_REGISTRY }}/hardware-mall-admin:${{ github.sha }}
    steps:
      - uses: actions/checkout@v4

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Login to registry
        uses: docker/login-action@v3
        with:
          registry: ${{ secrets.DOCKER_REGISTRY }}
          username: ${{ secrets.DOCKER_USERNAME }}
          password: ${{ secrets.DOCKER_PASSWORD }}

      - name: Build & push backend
        uses: docker/build-push-action@v5
        with:
          context: ./hardware-mall-backend
          push: true
          tags: |
            ${{ env.IMAGE_BACKEND }}
            ${{ secrets.DOCKER_REGISTRY }}/hardware-mall-backend:latest
          cache-from: type=registry,ref=${{ secrets.DOCKER_REGISTRY }}/hardware-mall-backend:buildcache
          cache-to: type=registry,ref=${{ secrets.DOCKER_REGISTRY }}/hardware-mall-backend:buildcache,mode=max

      - name: Build & push admin
        uses: docker/build-push-action@v5
        with:
          context: ./hardware-mall-admin
          push: true
          tags: |
            ${{ env.IMAGE_ADMIN }}
            ${{ secrets.DOCKER_REGISTRY }}/hardware-mall-admin:latest
          cache-from: type=registry,ref=${{ secrets.DOCKER_REGISTRY }}/hardware-mall-admin:buildcache
          cache-to: type=registry,ref=${{ secrets.DOCKER_REGISTRY }}/hardware-mall-admin:buildcache,mode=max

      - name: SSH deploy to server
        uses: appleboy/ssh-action@v1.0.0
        with:
          host: ${{ secrets.DEPLOY_HOST }}
          username: ${{ secrets.DEPLOY_USER }}
          key: ${{ secrets.DEPLOY_SSH_KEY }}
          script: |
            cd /opt/hardware-mall
            git fetch --all
            git checkout ${{ github.sha }} -- docker-compose.yml
            export IMAGE_TAG=${{ github.sha }}
            export DOCKER_REGISTRY=${{ secrets.DOCKER_REGISTRY }}
            # 用 sed 把 docker-compose.yml 里 build: 替换为 image: (CI 已 build 好)
            # 或者直接维护一份 docker-compose.prod.yml 仅用 image:
            docker compose -f docker-compose.prod.yml pull
            docker compose -f docker-compose.prod.yml up -d
            sleep 60
            docker compose ps
            curl -sf http://localhost:8080/actuator/health
```

- [ ] **Step 2: 创建 docker-compose.prod.yml（用预构建 image 而非 build）**

Create: `docker-compose.prod.yml`

```yaml
name: hardware-mall-prod

services:
  mysql:
    image: mysql:8.0
    container_name: hw-mysql
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: ${DB_ROOT_PASSWORD}
      MYSQL_DATABASE: ${DB_NAME:-hardware_mall}
      MYSQL_USER: ${DB_USERNAME:-hardware_mall}
      MYSQL_PASSWORD: ${DB_PASSWORD}
      TZ: Asia/Shanghai
    volumes:
      - mysql_data:/var/lib/mysql
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
      interval: 10s
      timeout: 5s
      retries: 10
    networks:
      - hw-net

  redis:
    image: redis:7-alpine
    container_name: hw-redis
    restart: unless-stopped
    command: redis-server --requirepass ${REDIS_PASSWORD} --appendonly yes
    volumes:
      - redis_data:/data
    healthcheck:
      test: ["CMD", "redis-cli", "-a", "${REDIS_PASSWORD}", "ping"]
      interval: 10s
      timeout: 5s
      retries: 10
    networks:
      - hw-net

  backend:
    image: ${DOCKER_REGISTRY}/hardware-mall-backend:${IMAGE_TAG:-latest}
    container_name: hw-backend
    restart: unless-stopped
    depends_on:
      mysql:
        condition: service_healthy
      redis:
        condition: service_healthy
    env_file:
      - /opt/hardware-mall/.env
    environment:
      SPRING_PROFILES_ACTIVE: prod
      DB_HOST: mysql
      REDIS_HOST: redis
    networks:
      - hw-net

  admin:
    image: ${DOCKER_REGISTRY}/hardware-mall-admin:${IMAGE_TAG:-latest}
    container_name: hw-admin
    restart: unless-stopped
    depends_on:
      - backend
    ports:
      - "80:80"
    networks:
      - hw-net

volumes:
  mysql_data:
  redis_data:

networks:
  hw-net:
    driver: bridge
```

```yaml
name: deploy-uniapp-experience

on:
  workflow_dispatch:
    inputs:
      desc:
        description: '版本描述'
        required: false
        default: 'CI 自动上传体验版'
  push:
    branches:
      - main
    paths:
      - 'hardware-mall-uniapp/**'

jobs:
  upload-experience:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 18
          cache: npm
          cache-dependency-path: hardware-mall-uniapp/package-lock.json

      - name: Install deps
        working-directory: hardware-mall-uniapp
        run: |
          npm ci
          npm install miniprogram-ci --no-save

      - name: Build mp-weixin
        working-directory: hardware-mall-uniapp
        run: |
          VITE_API_BASE_URL=${{ secrets.UNIAPP_API_BASE_URL }} npm run build:mp-weixin

      - name: Write wechat private key
        run: |
          mkdir -p ~/.wechat
          echo "${{ secrets.WEAPP_PRIVATE_KEY }}" > ~/.wechat/private.${{ secrets.WEAPP_APPID }}.key
          chmod 600 ~/.wechat/private.${{ secrets.WEAPP_APPID }}.key

      - name: Upload to experience
        working-directory: hardware-mall-uniapp
        env:
          WEAPP_APPID: ${{ secrets.WEAPP_APPID }}
          WEAPP_PRIVATE_KEY_PATH: ~/.wechat/private.${{ secrets.WEAPP_APPID }}.key
          CI_MODE: experience
          CI_VERSION_DESC: ${{ github.event.inputs.desc || 'CI 自动上传' }}
        run: node scripts/build-uni.js
```

# CI/CD 部署说明

## GitHub Secrets 清单

| Secret 名 | 用于 | 必填 |
|---|---|---|
| `DOCKER_REGISTRY` | 容器镜像仓库地址（阿里云 / Docker Hub） | ✅ |
| `DOCKER_USERNAME` | Registry 账号 | ✅ |
| `DOCKER_PASSWORD` | Registry 密码或 access token | ✅ |
| `DEPLOY_HOST` | 生产服务器 IP | ✅ |
| `DEPLOY_USER` | SSH 登录用户 | ✅ |
| `DEPLOY_SSH_KEY` | SSH 私钥 PEM 内容 | ✅ |
| `WEAPP_APPID` | 微信小程序 appid | ✅（如用 CI 上传体验版） |
| `WEAPP_PRIVATE_KEY` | 小程序上传密钥内容 | ✅ |
| `UNIAPP_API_BASE_URL` | prod 后端 URL（https） | ✅ |
| `JWT_SECRET_FOR_TEST` | CI 测试用 jwt secret | 可选 |

## 工作流

| workflow 文件 | 触发 | 作用 |
|---|---|---|
| `test.yml` | PR + push 到 main/phase* | 跑测试 + admin/uniapp 构建 |
| `backend-admin-deploy.yml` | push main 或手工 | 构建 push 镜像 + SSH 部署 |
| `uniapp-experience.yml` | push main 改 hardware-mall-uniapp/ 或手工 | 构建小程序 + 体验版上传 |

## 服务器预备文档

1. 创建 deploy 用户并加入 docker 组
2. 把 GitHub Actions 的 public key 加入 deploy 用户 `~/.ssh/authorized_keys`
3. clone repo 到 `/opt/hardware-mall`
4. 配 `.env` 真实环境变量（导入 `.env.example` 模板）
5. Prometheus / Grafana 容器（可选，自用项目可省）

## Rollback

```bash
ssh deploy@server
cd /opt/hardware-mall
export IMAGE_TAG=<上一个稳定 commit sha>
docker compose -f docker-compose.prod.yml pull
docker compose -f docker-compose.prod.yml up -d
```
