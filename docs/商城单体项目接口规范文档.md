## 一、接口概述

### 1.1 基础信息

| 项目 | 说明 |
|------|------|
| 基础 URL | `http://localhost:8080`（生产环境经 Nginx HTTPS 反代） |
| 路径前缀 | `/api` |
| 数据格式 | `application/json`（上传为 `multipart/form-data`，微信回调为原始 XML/JSON） |
| 字符编码 | UTF-8 |
| 认证方式 | `Authorization: Bearer <JWT>` |
| 时间格式 | `yyyy-MM-dd HH:mm:ss` |
| 金额 | 单位元，`DECIMAL(10,2)`，两位小数 |

### 1.2 统一响应格式

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

### 1.3 分页响应格式

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "records": [],
    "total": 100,
    "size": 20,
    "current": 1
  }
}
```

- `page` 从 1 开始；`limit` 由服务端按接口上限收敛（订单/商品/价格视角通常 20–50）。
- 列表筛选参数均为可选，未传表示不筛选。

### 1.4 鉴权与权限

| 标记 | 含义 |
|------|------|
| 公开 | 无需 Token |
| 可选登录 | 未登录按零售等级取价；登录后按用户等级取价 |
| 用户 | 需要用户端 JWT；缺失/过期返回 HTTP 401 |
| 管理员 | 需要管理端 JWT 且 `role=2`；否则 HTTP 403 |
| 微信回调 | 由微信签名校验，不走 JWT |

说明：

- `JwtInterceptor` 对 `/api/**` 生效；放行 `/api/user/login`、`/api/admin/login`、`/api/user/category/**`、`/api/user/logistics/**`、支付回调与微信消息推送。
- 用户端与管理端 Token 不通用；两端的 `refresh` 都会把旧 Token 加入 Redis 黑名单。
- 登录接口按 IP 限流（用户 10 次/分钟，管理员 5 次/分钟，支付预下单 10 次/分钟），超限返回 HTTP 429。

### 1.5 订单状态码

| status | statusText | 说明 |
|--------|------------|------|
| 1 | 待付款 | 订单创建，等待支付 |
| 2 | 待发货 | 已支付，等待发货 |
| 3 | 已发货 | 已发货，运输中 |
| 4 | 已完成 | 已确认收货 |
| 5 | 已取消 | 订单已取消 |
| 6 | 退款中 | 退款处理中 |
| 7 | 已退款 | 退款完成 |
| 8 | 退款申请中 | 用户已申请退款，等待管理员审核 |
| 9 | 退款失败 | 微信确认退款失败，等待管理员重试 |

### 1.6 支付状态码（payment_record）

| status | 说明 |
|--------|------|
| 0 | 待支付 |
| 1 | 已支付 |
| 2 | 已关闭 |
| 3 | 已退款 |
| 4 | 退款中 |

### 1.7 错误码

| code | HTTP | 说明 |
|------|------|------|
| 200 | 200 | 成功 |
| 400 | 200 | 参数校验失败（`message` 指明字段） |
| 401 | 401 | 未登录、登录过期、登录已失效 |
| 403 | 403 | 无管理端权限 |
| 429 | 429 | 请求过于频繁 |
| 40901 | 200 | 商品价格已变化，`data` 返回 `PriceChangeVO`（含最新预览） |
| 40902 | 200 | 幂等键已用于其他请求，需刷新幂等键后重试 |
| 500 | 200 | 业务异常或系统繁忙 |

> 除 401/403/429 由拦截器直接设置 HTTP 状态外，其余业务错误仍返回 HTTP 200，以 `code` 区分。

## 二、认证与用户（用户端）

### 2.1 微信登录

`POST /api/user/login` · 公开

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| code | string | 是 | `wx.login` 返回的临时登录凭证 |

响应 `data`：

```json
{
  "token": "eyJhbGciOi...",
  "userInfo": {
    "id": 1,
    "nickname": "微信用户",
    "avatarUrl": "https://...",
    "levelId": 1,
    "role": 1,
    "status": 1
  }
}
```

### 2.2 获取当前用户信息

`GET /api/user/info` · 用户

返回 `User`：`id`、`openid`、`nickname`、`avatarUrl`、`phone`、`province`、`city`、`role`、`levelId`、`status`、`createTime` 等。

### 2.3 更新用户资料

`PUT /api/user/info` · 用户

请求体为 `User` 的可编辑字段（`nickname`、`avatarUrl` 等），服务端强制使用当前登录用户 ID。

### 2.4 刷新 Token

`POST /api/user/refresh` · 用户

请求头携带旧 Token；返回新 Token，旧 Token 在剩余有效期内进入黑名单。

### 2.5 绑定手机号

`POST /api/user/phone` · 用户 · 限流 10 次/分钟

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| code | string | 是 | 微信手机号快速验证 code |

### 2.6 更新用户地区

`PUT /api/user/region` · 用户

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| province | string | 否 | 省份 |
| city | string | 否 | 城市 |

### 2.7 退出登录

`POST /api/user/logout` · 用户

将当前 Token 加入黑名单。

### 2.8 上传头像（用户端）

`POST /api/user/upload/avatar` · 用户 · `multipart/form-data`

字段 `file`；返回 `{ "url": "https://..." }`。限制 jpg/png/gif/webp，单文件不超过 10MB。

`UserLevelVO`：`id`、`name`、`isRetail`、`sortOrder`、`status`、`userCount`。

### 6.2 等级分类倍率

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/admin/user-level/{id}/rates` | 该等级全部分类倍率 |
| PUT | `/api/admin/user-level/{id}/rates` | 批量保存倍率 |
| POST | `/api/admin/user-level/{id}/rates/fill` | 用一个倍率填充所有缺口分类 |
| POST | `/api/admin/user-level/{id}/rates/copy` | 从其他等级复制倍率 |

`GET /{id}/rates` 响应：

```json
[
  { "categoryId": 1, "categoryName": "锁具", "rate": 0.9000, "missing": false },
  { "categoryId": 2, "categoryName": "胶类", "rate": null, "missing": true }
]
```

- `missing=true` 表示倍率缺口（未配置），与显式配置 `1.0000` 必须区分展示。
- 倍率取值范围 `(0, 3.0000]`，非法值返回 400。
- 批量保存 Body：`{ "items": [{ "categoryId": 1, "rate": 0.9000 }] }`
- 填充 Body：`{ "rate": 0.9500 }`
- 复制 Body：`{ "sourceLevelId": 2 }`

### 6.3 等级价格预览

`GET /api/admin/user-level/{id}/product-preview` · 管理员

| 参数 | 类型 | 必填 | 说明 |

## 十、订单（用户端）

### 10.1 结算预览

`POST /api/user/order/preview` · 用户

```json
{
  "items": [
    { "skuId": 1, "quantity": 2 },
    { "skuId": 3, "quantity": 1 }
  ]
}
```

响应 `CheckoutPreviewVO`：

```json
{
  "items": [
    {
      "skuId": 1,
      "productId": 1,
      "productName": "防盗门锁 C级",
      "productImage": "https://...",
      "spec": "[{\"name\":\"颜色\",\"value\":\"金色\"}]",
      "price": 199.00,
      "quantity": 2,
      "subtotal": 398.00
    }
  ],
  "goodsAmount": 398.00,
  "freightAmount": 0.00,
  "payAmount": 398.00
}
```

- 预览与创建共用同一套等级定价；倍率缺口直接返回业务错误，不允许下单。
- 预览结果中的 `payAmount` 作为创建订单时 `expectedPayAmount` 的依据。

### 10.2 获取幂等键

`GET /api/user/order/token` · 用户

返回 `data` 为 32 位 UUID（无连字符），用于创建订单的 `X-Idempotency-Key`。载荷变化或收到 40902 时应重新获取。

### 10.3 创建订单

`POST /api/user/order/create` · 用户

请求头：`X-Idempotency-Key: <token>`（必填）

```json
{
  "items": [{ "skuId": 1, "quantity": 2 }],
  "addressId": 1,
  "logisticsId": 1,
  "expectedPayAmount": 398.00,
  "buyerRemark": "请小心轻放"
}
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| items[].skuId | long | 是 | SKU ID |
| items[].quantity | int | 是 | 数量 |
| addressId | long | 是 | 收货地址 ID（必须属于当前用户） |
| logisticsId | long | 否 | 物流方式 ID；自提可为空 |
| expectedPayAmount | decimal | 是 | 预览确认的应付金额；与实时结算金额不一致时返回 40901 |
| buyerRemark | string | 否 | 买家备注 |

行为：

- 同一幂等键 + 相同请求指纹重试返回原订单；指纹不同返回 `40902`。
- `expectedPayAmount` 必填；为空返回「请先确认应付金额」，与实时金额不一致返回 `40901`，`data` 携带最新预览。
- 库存扣减、订单、明细、购物车清理、幂等记录置成功在同一事务内完成。

### 10.4 订单列表与详情

## 十二、支付

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| POST | `/api/user/pay/prepay` | 用户 | 创建支付记录并发起微信 JSAPI 下单 |
| POST | `/api/user/pay/callback` | 微信回调 | 支付结果通知 |
| POST | `/api/user/pay/callback/refund` | 微信回调 | 退款结果通知 |
| GET | `/api/user/pay/query/{orderId}` | 用户 | 查询该订单的支付记录 |

`POST /api/user/pay/prepay` 请求体：`{ "orderId": 1 }`；响应为小程序 `wx.requestPayment` 所需参数（`timeStamp`、`nonceStr`、`package`、`signType`、`paySign` 等）。

微信回调：

- 请求头需带 `Wechatpay-Signature`、`Wechatpay-Nonce`、`Wechatpay-Timestamp`、`Wechatpay-Serial`。
- 验签失败返回失败应答；成功返回 `{"code":"SUCCESS","message":"成功"}`。
- 退款回调成功推进 `6 → 7` 并回补库存；明确失败推进 `6 → 9`，支付记录回到 `1`，等待管理员重试。

`PaymentRecord`：`id`、`orderId`、`outTradeNo`、`transactionId`、`amount`、`status`、`payTime`、`refundAmount`、`refundTime`。
