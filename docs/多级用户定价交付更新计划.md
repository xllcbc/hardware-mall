# 多级用户定价交付更新计划

状态：执行中

日期：2026-11-02

关联 Issue：`#13`

## 1. 发布目标

在一条干净的发布分支上完成多级用户定价收口，并通过一次 PR、一次隔离的
MySQL 8 / Redis 7 预发布验收和一次维护窗口完成发布。本计划只保留一个活跃
开发基线；历史集成树和原型通过 annotated tag 归档。

## 2. 固定决策

| 项目 | 决策 |
| --- | --- |
| 发布分支 | `codex/new-pricing-release`，从操作时最新的 `origin/main` 创建 |
| 种子提交 | 已验证定价集成树以单个 squash 提交导入 |
| 数据模型 | `sku.price` 为唯一零售基价，倍率由等级分类矩阵表达 |
| 倍率缺口 | 运行时按 `1.0000` 兜底，管理端保留“未配置”语义 |
| 缓存 | 商品缓存保持中性；定价缓存修改提交后立即失效，失败由 outbox 补偿 |
| 陈旧上限 | 定价缓存最长陈旧约五分钟 |
| 数据库迁移 | 只接受 production 原始 schema；发现旧批发价列时中止 |
| 旧模型 | 两档批发价设计与实施计划均标记 Superseded，不执行数据转换 |
| 发布方式 | 一次 PR；停写、备份、迁移、部署、清缓存、冒烟按维护窗口执行 |
| 回滚 | 恢复迁移前全库备份，并部署上一版镜像 |

## 4. 自动化门禁

### 后端

- JDK 17 编译通过。
- H2 快速单元测试通过。
- 真实 MySQL 8 迁移测试通过：表、字段、索引、唯一约束、零售等级、
  用户默认等级和订单快照列。
- 真实 Redis 7 测试通过：事务提交后失效、回滚无副作用、失败补偿与告警。
- HTTP 验收覆盖访客、零售、非零售、倍率缺口、显式 `1.0000`、
  `exclude_discount`、购物车和订单快照。

### 管理端与用户端

- 管理端生产构建通过。
- 价格视角、用户等级深链、矩阵影响确认和取消无写请求通过浏览器验收。
- 约 1280px 视口下默认商品页和用户页无横向滚动。
- 图标操作具备 Tooltip、键盘焦点和可访问名称。
- 用户端不展示等级名称、倍率、划线价或批发标签。
- 小程序生产构建通过，并使用体验版验证首屏价格、购物车和下单。

## 5. 迁移与发布门禁

发布前必须完成：

1. 使用 production schema 快照在隔离环境启动 MySQL 8 和 Redis 7。
2. 执行 schema preflight；发现旧批发价字段即中止。
3. 保存全库备份并记录校验值。
4. 执行迁移、数据一致性检查和匿名/零售/多等级 E2E。
5. 提前创建 PR，确认全部 CI、构建和浏览器验收通过。
6. 维护窗口内停写、备份、迁移、部署、清理旧缓存并执行冒烟。
7. 验证商品列表、详情、购物车、订单和支付前金额使用同一等级结算价。
8. 验证订单等级快照不随后续倍率修改而变化。

## 6. 缓存清理

部署新版本后清理旧商品与定价缓存，并记录清理前后 key 数量：

```text
product:detail:v3:*
product:list:v3:*
product:recommend:v3
product:search:v1:*
pricing:level:*
pricing:retail-level-id
```

不得清理 `sku:stock:*`。缓存清理失败时停止发布，不以等待 TTL 代替。

- 部署上一版镜像并验证健康检查。
- 重新验证旧 Token、商品价格和订单创建。
- 保留本次发布日志、缓存补偿状态和回滚结果。
