# ADR-0004：批发基价与等级分类倍率

- 状态：Accepted
- 日期：2026-11-09
- 关联 Epic：#30
- 取代：ADR-0001 中的 schema 命名与倍率缺口行为

## 背景

`sku.price` 当前保存的是基准商品金额。后续定价方向要求把它解释为批发基价，
所有用户等级（包括零售）都通过等级分类倍率计算成交价，并且缺口不得向用户
泄漏批发基价。ADR-0001 的零售基价表述、旧表名和缺口按 `1.0000` 兜底规则
不再适用。

## 决策

1. `sku.price` 金额保持不变并作为批发基价；SPU 无 SKU 时使用
   `spu.original_price`。
2. 等级分类倍率表命名为 `level_category_rate`，订单倍率快照列命名为
   `order_item.pricing_rate`。
3. 所有启用等级都参与矩阵；零售等级也通过矩阵取价，但不可改名、停用或删除。
4. 倍率范围为 `(0, 3.0000]`。
5. 任意等级的分类倍率缺口均视为“暂不可售”，不再按 `1.0000` 兜底。
6. `exclude_discount` 商品固定按零售等级结算价。
7. 旧倍率全部清空，不做绝对批发价到倍率的数值换算。
8. 系统尚未正式运营，不设计旧字段双轨兼容或历史基价快照。

## 后果

- 数据库需要一次从 2026-11-02 schema 到新命名的增量迁移。
- 发布门禁必须在缺口、购物车、订单和商品展示链路上保持失败关闭。
- 缓存 key 和商品价格视图需要随 WB-05 至 WB-07 继续升级。
- ADR-0002 的缓存失效边界和 ADR-0003 的商品缓存新鲜度约束继续有效。

## 备选方案

- 继续使用 `level_category_discount` / `discount_rate`：名称表达的是折扣而非
  可大于 1 的定价倍率，未采用。
- 为不同等级保存 SKU 绝对价格：字段膨胀且无法表达分类维度，未采用。
- 缺口回落到零售倍率：会向普通用户泄漏批发基价，未采用。
