# ADR-0002：定价缓存提交后直接失效并设置五分钟上限

- 状态：Accepted
- 日期：2026-11-03
- 关联 Issue：`#18`
- 关联设计：`docs/多级用户定价设计文档.md`

## 背景

等级分类倍率变更必须在数据库提交后尽快生效。原实现使用一小时缓存，
且缓存删除和重建会无限等待分布式锁；Redis 失效失败时，旧价格可能持续
暴露一小时，提交后的管理请求也可能被锁拖住。

当前数据规模为等级分类矩阵的少量 key，不需要引入持久化 outbox、后台重试
任务和额外数据库表。更重要的是把正常失效路径做快，并让失败路径有明确上限。

## 决策

1. 矩阵保存、填充、复制以及等级状态变化通过事务事件在提交后触发缓存失效。
2. 事务回滚时不执行 Redis 删除；缓存失效失败不回滚已提交业务数据。
3. 当前阶段不引入 outbox，也不建设定价缓存专属指标与告警。失效失败记录日志，
   由 TTL 兜底。
4. 缓存删除与缓存重建使用同一把 Redisson 锁，并设置有限等待时间。等待超时后
   失效请求立即返回，重建请求直接回源且不写缓存。
5. 定价缓存基础 TTL 为 240 秒，叠加 0 至 60 秒随机抖动，硬上限为 300 秒。
6. 发布流程主动删除 `pricing:*` 旧缓存，不能依赖 TTL 等待旧实现退出。

## 后果

- 正常路径在数据库提交后立即删除定价缓存，不需要后台补偿任务。
- 失效失败时价格最长陈旧 300 秒；运维指标与告警暂缓，待基础发布稳定后重新评估。
- 不增加 outbox 表、重试任务和双写事务，减少当前发布面的复杂度。
- 如果未来失效失败率或恢复时效不再满足业务要求，应通过新的 ADR 重新评估
  持久化补偿方案。
