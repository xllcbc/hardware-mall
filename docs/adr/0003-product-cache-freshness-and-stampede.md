# ADR-0003：价格相关商品缓存采用五分钟新鲜度与有界防击穿

- 状态：Accepted
- 日期：2026-11-04
- 关联 Issue：`#23`
- 关联 ADR：`0001-multi-level-pricing.md`、`0002-pricing-cache-bounded-invalidation.md`
- 关联设计：`docs/商品缓存边界与依赖.md`

## 背景

多级用户定价的商品页面和订单金额都依赖中性商品缓存中的零售基价。当前 SKU 基础信息、商品列表、详情和推荐缓存最长可陈旧一小时，搜索缓存为十分钟；这比定价倍率允许的五分钟陈旧窗口更长。

商品列表、详情、推荐和搜索仍然使用无上限的缓存重建锁等待。锁持有者异常时，其他请求可能长期等待。库存缓存没有使用与重建一致的锁执行失效，库存读取和批量补齐也没有 singleflight，可能在失效与回填并发时写回旧库存。批量 SKU 获取在抢锁失败时直接查库，虽不写缓存，但没有在拿锁后再次检查其他实例是否已经完成回填。

## 决策

1. `sku:info`、商品列表、详情、推荐和搜索等包含零售基价或 SKU 价格的缓存使用 240 秒基础 TTL 和 0-60 秒抖动，最长陈旧时间不超过 300 秒。
2. 商品查询缓存的重建锁使用可配置等待上限，默认 500ms。等待超时后直接回源数据库且不写缓存，不能无限阻塞请求。
3. 库存缓存的读取、批量补齐和失效使用同一把按 SKU 的锁。未命中读取采用有界 singleflight，失效使用带锁删除。
4. 批量 SKU 获取按 SKU 排序获取锁，拿到锁后再次批量读取，只回源仍然缺失的 SKU。抢锁超时允许退化为直接查库，但不得写缓存。
5. 商品缓存失效失败记录 Micrometer 指标和告警。当前仍不引入 outbox 或持久失效队列。
6. 库存数据库原子扣减仍是超卖判断的唯一事实来源，缓存只服务展示和预检查。

## 后果

- 价格相关商品缓存与定价缓存拥有相同的五分钟陈旧上限。
- 商品列表、详情和搜索的回源频率会提高，换取更短的价格错误窗口。
- 锁竞争时部分请求会退化为直接查库且不写缓存，避免无限等待，但数据库瞬时压力可能上升。
- 库存缓存失效与回填不再存在旧值覆盖窗口；缓存失败仍由短 TTL 和现有库存补偿兜底。
- 不增加 outbox、worker、死信和持久失效队列表。

## 备选方案

- 保持一小时商品缓存并只增加告警：实现较少，但价格错误窗口仍明显超过业务接受范围。
- 为商品缓存增加 outbox：可持久重放失效，但增加表和后台任务复杂度，当前五分钟 TTL 可覆盖失败窗口。
- 完全移除商品缓存：一致性最直接，但会把商品列表和详情读流量全部压到 MySQL。
- 所有请求强制等待唯一回源者：singleflight 最强，但锁异常时会放大请求等待和可用性风险。
